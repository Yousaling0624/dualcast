# 叠播 DualCast

把两个 B 站直播间叠在一起看的 Android 客户端：**B 房间出画面和声音，A 房间出声音和弹幕**，A 的弹幕直接盖在 B 的画面上。

> 当前版本 **v1.1.1**（versionCode 13，包名 `com.dualcast.live.debug`）。设置页「关于」和首页标题下都会显示版本号，用来确认装的是哪一次构建。
>
> **1.1.1 改动**：解说小窗改成手势调尺寸——拖四角保持 16:9 等比缩放，拖四边改窗口比例、画面铺满裁切不留黑边；去掉了容易点错的「三档大小」按钮，右上角只剩全屏 / 关闭；收起聊天室后的「聊天室」胶囊跟随控制条一起出现、一起自动消失，不再常驻挡画面；顶栏补回画中画按钮；竖屏播放时画面顶部给挖孔 / 状态栏留出空间，不再被摄像头咬住。
>
> **1.1.0 改动**：设置页改成「一级入口 + 二级详情」，外观 / 弹幕 / 播放 / 账号 / 关于各自独立，首页和设置页都补了底部安全区；首页「开始叠播」常驻底部，不用再滚到底；画面与聊天室改成单调用点布局，收起 / 展开聊天室只改尺寸、不重建播放器；新增页面滑动转场、抽屉 tab 淡入淡出、聊天弹幕淡入和全局按压缩放反馈；播放页顶栏按钮统一高度，全页面都让背景铺进挖孔区。
>
> **1.0.10 改动**：A 解说小窗平时只留画面，点一下才浮出「大小 / 全屏 / 关闭」和倍率提示，停手 3 秒自动淡出；新增三档大小按钮，右下角拖拽手柄也加大加亮了，不用再猜哪里能调大小。
>
> **1.0.9 改动**：聊天室可以收起，画面一键铺满；新增一键全屏（锁横屏、显示退出全屏按钮）；全屏时点一下飘过的弹幕就能「+1 / 回复」，不用回聊天室；A 解说小窗也能全屏，放大裁切取景后退出仍是同一个小窗；去掉 666 / 好耶之类的快捷短语，输入框只发自己打的字；弹幕层与聊天栏避开挖孔和状态栏，横屏摄像头不再挡字。
>
> **1.0.8**：播放页改成「上面画面、下面聊天室」的直播间布局（横屏左右分栏）；删掉起播缓冲，连上就播；聊天室里单击弹幕即可「+1 / 回复」；新增一键重连和首页「我的组合」。
>
> **1.0.5 起移除了虎牙支持。** 虎牙的 FLV 长连接在移动网络下会被 CDN 周期性掐断，实测拿不到稳定播放，与其留个半残的入口，不如只把 B 站做扎实。

- 平台：哔哩哔哩（A/B 两路都是 B 站，任意两个直播间自由组合）
- 语言：Kotlin + Jetpack Compose
- 设计：Material 3 Expressive 风格（大圆角、夸张字号、弹性动效），支持莫奈取色（Android 12+ 直接读壁纸，低版本用种子色生成整套 tonal palette）
- 播放：Media3 / ExoPlayer 双实例，B 画面 + B 声音 + A 声音同时输出，音量独立可调，连上即播

> 仅用于个人学习与自用。请遵守各平台服务条款，不要用于二次分发、商业直播或其他侵权场景。

## 1. 功能

| 模块 | 说明 |
| --- | --- |
| 双路解析 | 粘链接或房间号即可，输入 `live.bilibili.com/6` 或 `6` 都能认 |
| 直播间布局 | 竖屏上面是 16:9 画面、下面是聊天室，和 PiliPlus 的直播间一致；横屏改成左画面右聊天，不浪费横向空间；聊天室右上角可收起，收起后右下角留一个「聊天室」胶囊随时叫回来 |
| 一键全屏 | 顶栏全屏按钮：收起聊天室、画面铺满并锁横屏；再点一次（或按返回）退出全屏，回到进入前的布局 |
| 画面合成 | B 的画面全屏渲染；A 平时只解音频，打开小窗才解视频，关掉立刻释放解码器 |
| 解说小窗 | 顶栏「小窗」或画面面板打开 A 主播画面。可拖动、双指缩放画面、双指平移取景、双击 1×/2× 切换；点一下画面浮出按钮，停手 3 秒自动淡出。**拖四角**：窗口保持 16:9 等比缩放；**拖四边**：改窗口比例，画面按铺满裁切，不留黑边——想框住主播摄像头直接把边往里拖就行。右上角还能把整个小窗全屏，双指放大裁切到主播摄像头那块，再退出全屏就变回原来大小的小窗，取景保持不变。进画中画 / 后台自动释放 A 的视频解码 |
| 声音混合 | B 原声 + A 原声同时播放，两路音量独立滑杆，一键「只听 A / 只听 B / 双声道」 |
| 声音对齐 | 步进按钮「−0.5s / −0.1s / +0.1s / +0.5s」：点「+」A 暂停一下（声音往后挪），点「−」A 用 1.5 倍速追一段（声音提前），每次都有明确听感；「归零」把手动偏移清掉 |
| 混音记忆 | 按「A 房间 + B 房间」组合记住两路音量和声音偏移，最多 40 组；A/B 对调后也能镜像找回。下次开播自动还原，不再每次重调 |
| 我的组合 | 开播过的「主播 + 比赛」自动存成卡片，首页点一下重新解析并直接开播；最多 12 组，可单独删除 |
| 弹幕叠加 | A 房间弹幕通过 WebSocket 实时拉取，Canvas 自绘弹幕层，支持滚动/顶部、轨道避让、密度控制 |
| 弹幕样式 | 字号、透明度、速度、显示区域、描边/阴影/纯色、显示昵称、屏蔽词 |
| 高亮消息 | B 站醒目留言（SC）、礼物会以顶部高亮条展示 |
| 聊天室 | 画面下方是可滚动的聊天室，新弹幕自动跟随；往上翻会暂停跟随并出现「有新弹幕 ↓」，不会把人拽回底部 |
| 单击互动 | 聊天室里点一条弹幕就选中，底部出现「+1 / 回复」；全屏时直接点画面上飘过的那条弹幕，底部浮出同样的操作条，不用切回聊天室。+1 原样跟一条，回复自动拼成 `回复内容@对方:对方原话`，发送前能看到最终文案 |
| 发弹幕 | 聊天室底部常驻输入框，发到 A（主播）房间；字数计数、1.5 秒冷却，自己发的那条金色高亮。没有 666 / 好耶之类的快捷短语，发什么由你决定 |
| 一键重连 | 顶栏和聊天室都有刷新按钮：两路播放地址重新解析、弹幕重连；出错卡上也能直接点「重连」 |
| B 站登录 | 扫码登录（手机 B 站 App 扫一下）或网页登录（手机号/账号密码，在官方页面里完成校验），登录态拿来看原画、提升接口通过率 |
| 一键互换 | 播放页底栏「切画面」把 A / B 的画面、声音、弹幕来源整体对调；播放器实例不重建，切的时候保留上一帧，不会黑屏 |
| 后台播放 | 设置里打开后，切后台 / 锁屏继续出声，通知栏可停止；后台自动关掉视频解码省电 |
| 设置二级页 | 设置首页只放五张入口卡（账号 / 外观 / 弹幕 / 播放 / 关于），每项带当前状态摘要；点进去是独立二级页，返回键先回一级，不会直接退出设置 |
| 动效与适配 | 页面左右滑动转场、设置二级页推入、抽屉 tab 淡入淡出、聊天弹幕淡入、可点区域按下微缩；首页和设置页按 `safeDrawing` 避让，横屏挖孔不挡字，大屏内容限宽居中 |
| 清晰度切换 | 播放页顶栏显示 B 当前实际档位，点开可选原画 / 蓝光 / 超清 / 高清，只重载 B 的画面，A 的声音不中断 |
| 记忆组合 | A/B 两路的房间号会持久化，冷启动后自动回填并重新解析，不用每次重输 |
| 线路容错 | 每条流解析出多条 CDN 候选，播放失败 / 卡死自动切下一条；全部线路都卡住时重新解析地址再试 |
| 画中画 | 一键 PiP，切到别的 App 继续看 B 的画面 + 弹幕 |
| 主题 | 跟随系统 / 浅色 / 深色；莫奈取色可选「跟随壁纸」或「自定义种子色 / 从图片提取」 |
| 横屏 | 首页 A/B 并排（≥600dp 触发）、设置页双列、播放页左画面右聊天，转屏不重建 Activity，播放不中断 |
| 全面屏 | 播放页沉浸式铺满，画面延伸进挖孔区；顶栏、底栏、弹幕层、聊天栏都按 `safeDrawing` / `displayCutout` 自动避让，横屏时摄像头不会压住按钮和弹幕 |
| 历史 | 最近解析过的房间，一键回填 |

## 2. 构建

环境要求：

- Android Studio（Narwhal 及以上）或命令行 Gradle
- JDK 17+
- compileSdk 36（Android 16），minSdk 26，targetSdk 36

命令行：

```bash
# local.properties 里写好自己的 SDK 路径，例如
# sdk.dir=/Users/you/Library/Android/sdk

./gradlew :app:assembleDebug
# 产物：app/build/outputs/apk/debug/app-debug.apk
```

> 仓库里的 `local.properties` 不应提交，Android Studio 打开工程会自动生成。

依赖版本集中在 `gradle/libs.versions.toml`：

- AGP 8.13.2 / Kotlin 2.2.20 / Gradle 8.14.3
- Compose BOM 2025.06.01 + material3 1.4.0
- Media3 1.11.1（exoplayer / ui / datasource-okhttp）
- OkHttp 4.12、Coil 2.7、Palette 1.1、DataStore 1.1.7、Brotli 0.1.2、ZXing core 3.5.3（只用来生成二维码矩阵）

### 关键实现

**B 站接口的 WBI 签名**：`getDanmuInfo` 这类直播接口在服务端加了 WBI 校验，请求必须带 `wts`（秒级时间戳）和 `w_rid = md5(按 key 排序后的 query + mixinKey)`。`mixinKey` 由 `nav` 接口下发的两个图片名按固定表重排后取前 32 位，每天会变，代码里缓存一小时。**缺签名一律返回 `-352`，这和 Cookie、登录状态完全无关**。

**扫码登录**：走 `passport.bilibili.com` 的公开接口，`qrcode/generate` 拿 `qrcode_key`，本地用 ZXing 的编码器直接取模块矩阵、Compose Canvas 逐格绘制（不生成 Bitmap）。轮询 `qrcode/poll` 时注意：**外层 `code` 恒为 0，真正的状态在内层 `data.code`**（86101 未扫码 / 86090 已扫码待确认 / 86038 过期），Cookie 从响应头的 `Set-Cookie` 里取。网页登录则用一个 WebView 打开官方 H5 登录页，登录完成后从 `CookieManager` 读同一个域下的 Cookie。

**双路播放**：`DualPlayer` 持有两个 `ExoPlayer`。A 路默认通过 `trackSelectionParameters.setTrackTypeDisabled(TRACK_TYPE_VIDEO, true)` 关掉视频轨道，只留音频；打开解说小窗时才把视频轨道解回来，并用一个 `TextureView` 版 `PlayerView` 接在 A 的播放器上（默认 `SurfaceView` 裁不了圆角）。小窗关闭或进 PiP / 后台时立刻把 A 的视频轨道关掉，释放解码器。

**起播**：直播流没有历史数据可 seek，也没必要先攒一段——连上就播，`DefaultLoadControl` 用 3 秒 / 15 秒的小水位，延迟更低。抗抖交给看门狗和换线：播放位置 25 秒不动就换 CDN，线路耗光就重新解析地址。

**播放页布局**：竖屏是 `Column`（16:9 画面 + 聊天室），横屏是 `Row`（画面 `weight(1f)` + 330dp 聊天栏）。控制条、弹幕浮层、解说小窗都被限制在画面区内，不再压到聊天室；聊天输入框单独吃 `imePadding`，键盘弹起时不会把画面一起压扁。

**声音对齐**：两个直播间是两条独立的流，起播时间天然差几百毫秒。这里**不用 `AudioProcessor`**——在 AudioSink 里插处理器依赖解码链路走 PCM，很多机型会走 audio offload 直接绕过去，从外部完全验证不了「到底有没有生效」，之前几版就栽在这上面。现在直接控制播放器：

- 让 A 更晚：`audioPlayer.pause()` N 毫秒再 `play()`。暂停期间 B 照常播，A 恢复后位置没动，就永久落后 N 毫秒。多次点击累加到同一个截止时间，不会互相打断。
- 让 A 更早：`audioPlayer.setPlaybackSpeed(1.5f)` 跑 `N / 0.5` 毫秒再恢复 1.0。走 ExoPlayer 自带的 Sonic，变速不变调，听感只是「语速快了一点」。
- 归零：按当前累计值反向操作一次（快放或停顿），听感上一定有反应。

**混音记忆**：`RoomProfile` 以 `A 房间号|B 房间号` 为 key，把两路音量和 `offsetMs` 存进 DataStore，最多保留 40 组；写入做了 500ms 防抖，拖音量滑杆不会每一帧都落盘。开播时先查正序，查不到再用反序做一次镜像（音量对调、偏移取反），所以「把 A/B 对调」之后同一对房间也能恢复。偏移等两路都真正 `isPlaying` 后再执行一次暂停 / 快放；重连或换边把播放器拉回直播边缘后，会延迟 1.5 秒把同样的偏移补一次，数字和听感不会脱节。

**我的组合**：`RoomCombo` 同时存 A/B 的输入串、房间号、标题和主播名。每次成功开播自动写一条（按房间号去重，最多 12 组），首页用横向卡片展示，点击时先重新解析两个房间再开播；首页不用额外请求接口就能显示标题。

**聊天室与回复**：弹幕进聊天室时分配一个单调递增的本地 `seq` 当 LazyColumn 的 key，避免重复 dmid 造成 key 冲突。单击只做「选中」，不直接发——误触代价太大；选中后底部出现「+1 / 回复」。B 站直播没有楼中楼，`reply_mid` / `replay_dmid` 那套在部分场景会被服务端当成格式不完整的回复，所以 1.0.8 改成纯文本：`{回复内容}@{对方昵称}:{对方原话}`，由 `DanmakuText` 按 20 字上限分配额度，优先保住回复内容，再截断原话。

**发弹幕**：`POST https://api.live.bilibili.com/msg/send`，query 带 WBI 签名的 `web_location=444.8`，表单里 `csrf` 与 `csrf_token` 必须都等于 Cookie 里的 `bili_jct`，`rnd` 每次现取秒级时间戳（服务端拿它做重放校验）。发送成功后本地先插一条并记下文案，8 秒内收到 WebSocket 回显就直接丢掉，避免同一条出现两次。

**弹幕层**：`DanmakuOverlayView` 是原生 View，Compose 里用 `AndroidView` 包一层。原因很实际——直播弹幕密度高，Compose 的文本测量 + 布局开销扛不住。轨道用「上一条弹幕完全进入屏幕 + 间距」计算可用时间，速度恒定所以不会追尾；顶部弹幕单独占用轨道 4.2 秒。

**全屏与点选弹幕**：全屏只改播放页状态（收起聊天室 + `requestedOrientation = SENSOR_LANDSCAPE`），不重建播放器；退出时还原进入前的聊天室状态。点飘过的弹幕不走 View 的 `onTouchEvent`——上层 Compose 手势统一接点击，再用弹幕层的坐标做命中检测（`findMessageAt`），没点中就走原来的「开关控制条」，避免 AndroidView 吃掉 `DOWN` 导致点画面失灵。命中后闪一圈高亮，并浮出 +1 / 回复操作条。

**挖孔适配**：Activity 在播放页把 `layoutInDisplayCutoutMode` 设为 `ALWAYS`（API 30+）/ `SHORT_EDGES`，画面延伸到摄像头周围；顶栏、底栏用 `safeDrawing`，聊天栏按 `displayCutout` 的右侧内边距让开，弹幕层的可用区域也扣掉状态栏与挖孔。

**莫奈取色**：`Monet.kt` 把种子色转到 HSL，按 Material 的 L\* 色调阶梯（10/20/30/40/80/90…）生成 primary / secondary / tertiary / neutral / neutralVariant 五组色板，再用 CIE 相对亮度把每个色调校正回规范位置。Android 12+ 优先走 `dynamicLightColorScheme` / `dynamicDarkColorScheme`，低版本或自定义种子色走这套生成器。

**MD3E 样式**：material3 1.4.0 的 `MaterialExpressiveTheme` 仍是 internal API，所以这里用 `MaterialTheme` + 自定义大圆角 `Shapes`、夸张字阶 `Typography`、`spring` 动效和胶囊化组件来实现 Expressive 观感。

## 4. 使用

1. 首页上方卡片是 **A（弹幕 + 声音）**，下方是 **B（画面 + 声音）**，中间按钮可交换。横屏时两张卡片会并排。
2. 粘链接或房间号，点输入框右侧箭头解析。解析成功会显示封面、标题、主播、开播状态。
3. 点「开始叠播」，连上就出声。首页有「我的组合」时可以直接点卡片，自动重新解析并开播。
4. 播放页上方是画面，下方是聊天室。点画面显示/隐藏控制条，「混音 / 清晰度 / 画面」在底部抽屉里，聊天室右上角的小齿轮直接开弹幕设置。聊天室右上角的向下箭头可收起聊天室；顶栏的全屏按钮会收起聊天室并锁横屏，再点一次或按返回退出。
5. **两路声音对不齐**：播放页 → 混音 → 声音对齐。先「只听 A」「只听 B」来回切两次，判断谁快谁慢；A 慢就点「+」（A 会停一下往后挪），A 快就点「−」（A 会快放追上来）。调到两路说话不打架即可，右上角「归零」清掉手动偏移。
6. **想看主播摄像头**：顶栏开「小窗」，单指把窗口拖到合适位置，双指放大画面并挪到摄像头那一块，再拖右下角把窗口改小。小窗右上角还能点全屏，把 A 画面铺满整个画面区，放大裁切好主角的脸再退出全屏——窗口变回原来的大小，取景还是刚才那块。双击画面可以 1×/2× 快速切换，左下角「×2.0 · 复位」一键还原。
7. **发弹幕 / 互动**：聊天室底部输入，发到 **A 房间**（主播那一路）——B 只是找来的比赛画面，发到那里没人看得到。点聊天室里任意一条弹幕，会出现「+1 / 回复」；全屏时直接点画面上飘过的那条弹幕，底部会浮出同样的操作条。回复会显示最终文案预览。
8. **卡住 / 换了网络**：点顶栏或聊天室右上角的刷新图标，两路地址会重新解析、弹幕重连；出错卡上也有「重连」。
9. 设置页可以改主题、莫奈取色、清晰度、弹幕默认样式。

## 5. 已知限制（重要）

这些是实际跑接口、抓包验证后得到的结论，不是拍脑袋：

1. **不再预缓冲。** 1.0.8 删掉了 30 秒起播缓冲：直播流本来就不给历史数据，先停着攒既拖慢开播，也解决不了 CDN 掐连接。现在连上就播；真卡住时看门狗 25 秒判定并换线，顶栏也能手动重连。

2. **B 站弹幕已修复，但风控仍可能拦。** 之前一直「重连中」的根因是 `getDanmuInfo` 缺 WBI 签名，已补上：签名后实测能拿到 token，WebSocket 认证回 `{"code":0}`，也能正常收到 `INTERACT_WORD_V2`、`ENTRY_EFFECT` 这类服务端推送。如果某些网络环境下仍然 `-352`，先换网络；登录后带上 `SESSDATA` 通过率会更高。弹幕认证失败时，代码会自动退回匿名再试一轮。

3. **清晰度受账号限制。** 未登录时 B 站只给到流畅/高清，请求 `qn=10000` 也会被降级，这是服务端行为。扫码登录后可以拿到原画。

4. **直播地址有时效。** B 站 FLV/HLS 地址带 `expires`，一般几小时后失效；重新进房会重新解析。长时间挂机后如果报 403，点一下重连即可。

5. **直播长连接不能用带整通超时的 HTTP 客户端。** 拉流复用接口用的 OkHttp（`callTimeout=25s`）会在 25 秒时掐断整条请求，表现就是「放一会儿卡住」。现已拆出专用客户端（`callTimeout=0`，只保留 12 秒读超时），并加了看门狗：播放位置 25 秒不动就切线路，线路全挂了重新解析地址。

6. **声音对齐只动音频，不动 B 的画面。** 让 A 延后时 B 的画面不变，所以极端值（超过 1 秒）下两路的「口型」会明显错开——这本来就是两条不同的直播流，对的是声音，不是画面。

7. **回复不是真正的楼中楼。** B 站直播没有回复接口，发出去的就是一条普通弹幕 `回复内容@对方:对方原话`，对方不会收到专门的回复提醒。20 字上限下，`DanmakuText` 会优先保留你的回复内容，再截断对方原话。

8. **发弹幕必须登录，且有条数限制。** 未登录时输入框上方会显示「去登录」，点 +1 / 回复也会提示。B 站单条上限 20 字，连续发送约 1.5 秒一条，超了会返回 `10032`（被禁言）/ `10031`（太快）/ `10030`（敏感词），这些错误码都已翻成中文提示。

9. **录制/推流没有做。** 当前是「本机合成预览」，不是把合成结果编码成一路流。要做录播或推流，需要再加 MediaCodec + MediaMuxer / RTMP。
